# 裁剪决策表 — 为什么这个记账 App 只有 3 个域

> 本文是本项目作品集叙事的核心文档：逆向一个 90 张数据表的成熟记账产品后，**哪些域被保留、哪些被有意砍掉、为什么**。
> 逆向方法与发现详见 [匿名化架构分析报告](03-tech/anon-report.md)（静态分析，未运行目标 App）。

## 结论先行

| | 原产品 | 本项目 |
|---|---|---|
| 数据实体 | 90 张表（schema version 2761，数百次迁移） | 4 张表（account / category / bill / budget） |
| 页面 | 3400+ Activity、10 个桌面组件 | 5 个页面、3 个页签 |
| 网络依赖 | 192 个云接口 + 对象存储 + WebDAV 同步 | 0（除语音模型本地包，永不联网） |
| 权限 | 27 项（含无障碍、悬浮窗、位置） | 1 项（RECORD_AUDIO） |

**裁剪原则**：目标用户是"记不住操作、也不觉得需要记账"的老人，唯一入口是替他们安装的子女。凡是老人用不到、或者增加理解成本/隐私风险的东西，一律砍掉。

## 一、保留的域（3 个）

| 域 | 原产品对应实体 | 保留理由 | 本项目实现 |
|---|---|---|---|
| 记账主流程 | Bill、ParentCategory/ChildCategory、Tag | 老人场景的唯一核心动作；两级分类足够（一级 8 类 + 二级），标签对老人是干扰 | `bill` + `category` 表，语音确认卡 + 手动表单 + 明细编辑 |
| 预算 | Budget、CategoryBudget、BudgetSetting | "预算剩多少"是老人/子女最容易理解的进度条；按分类设预算会增加输入负担，砍 | `budget` 表仅月度总预算，0 表示不设 |
| 汇总统计 | （Statistics* 4 实体的功能面） | 子女远程查看父母消费是否异常的窗口；日/月/年三档比原产品的桑基图/趋势图更直白 | `periodsSummary()` + 分类占比条形列表 + CSV 导出 |

## 二、砍掉的域（87 个实体的归属）

### 2.1 老人用不到（功能性裁剪）

| 原产品域 | 实体（约数） | 砍掉理由 |
|---|---|---|
| 多账本/协作 | AccountBook 及成员/分享/隐藏 | 老人只有一本账；"分享给家庭成员"是年轻家庭需求 |
| 资产/负债体系 | Asset* 7 实体、Loan* 3、Lend、Instalment、RepaymentClose、Reimbursement | 体量最大（近 40 个 Activity）；信用卡账单日/房贷摊薄超出老人心智模型，且老人交由子女管理大额资产 |
| 投资理财 | StockAsset/StockInfo/StockPrice/GoldPrice/FundInfo/CostMethod、Currency 多币种 | 老人不盯盘；多币种换算对目标用户是纯噪音 |
| 拆账/关联账单 | SplitGroup/SplitMember/SplitExpense、RelatedBill | AA 制是年轻人场景 |
| 桌面小组件 | Widget* 系列（10 个组件 + 快速设置磁贴） | 老人不长按桌面加组件；首页大按钮就是入口 |
| 标签体系 | Tag | 与二级分类功能重叠，多一层输入成本 |
| 梦想/心愿 | Dream | 情感化设计，与记账核心无关 |
| 节假日 | LegalHolidayInfo | 仅服务于"按月统计排除节假日"这类高级统计 |
| 首页运营位 | HomeBanner | 广告/运营位，与"永无广告"承诺相反 |

### 2.2 自动化与 AI 高级功能（老人不信任，老人场景反而有害）

| 原产品域 | 实体（约数） | 砍掉理由 |
|---|---|---|
| 自动记账（无障碍） | Auto* 5 实体 + 294 类 | 原产品监听 28 个 App 的窗口内容——对老人是"手机被监视"的不安感，权限面过大；本项目的语音录入是老人唯一愿意主动做的输入方式 |
| 截图/AI 识别 | recognize 37 类 + STS 上传 | 财务截图离开设备（上传 OSS），违背"数据不出手机"承诺；自研方案用本地 Vosk 模型替代 |
| 智能分类 | AiType | 自研的中文热词纠错 + 关键词分类规则（纯 Java 可单测）在记账短句场景足够，且可解释 |

### 2.3 云与同步（违背"永不联网"承诺，整域砍）

| 原产品域 | 说明 | 砍掉理由 |
|---|---|---|
| 云账号/增量同步 | UserDB/UserInfo、192 个接口、API 路由下沉 native | 老人不会注册账号；子女不必注册第二账号。代价：换手机靠 CSV 导出（REQ-003），接受 |
| WebDAV 备份 | Backup 实体 | 原产品的备份 zip 未加密，账单原文进第三方网盘是真实的隐私风险；本项目数据只在本机 |
| 主题/皮肤 | Theme* 3 实体 | 个性化是年轻用户需求；老人要的是稳定不变的界面 |

### 2.4 配置类与高级统计（保留其 10%，砍掉 90%）

| 原产品域 | 实体 | 裁剪方式 |
|---|---|---|
| 统计设置 | StatisticsSetting/Content/Sort/Module 4 实体 | 砍掉全部自定义，固定为"日/月/年 + 分类占比"，减少设置项 |
| 导入导出 | ImportManager/Parameter/Setting | 砍掉 Excel/支付宝/微信账单导入与 AI 导入（老人没有历史账单要迁）；保留**单向 CSV 导出**这一个动作 |
| 界面自定义 | TabWeight/FunctionWeight、CustomModule* | 砍掉；页签固定为 记账/明细/汇总 |
| 历史记录 | IconSearchHistory/ColorHistory/DateHistory/PermissionHistory、CategoryModifyHistory | 砍掉；均为高频操作 App 的效率优化，老人操作频率低 |
| 通知 | Notify/NotifySettingConfig | 砍掉记账提醒推送（老人对推送的反感大于提醒价值） |
| 共享分类 | CategoryKey | 依赖多账本/云账号体系，上游已砍 |

### 2.5 账号与安全（以极简方式重建）

| 原产品域 | 原产品做法 | 本项目做法 |
|---|---|---|
| 用户体系 | email/手机号/三方登录（微信/QQ/微博）、VIP | 无账号。数据归属 = 这台手机 |
| 数据保护 | 数据库明文 + WebDAV 未加密备份（原产品风险点） | 同为明文 SQLite，但**数据永不离开设备**，泄露面收敛到物理接触；若日后加密，优先级高于云同步 |

## 三、被砍功能里"最舍不得"的三个与为什么不砍回来

1. **自动记账（无障碍）**：对年轻人是杀手级功能，对老人是惊吓源（"它怎么知道我付了钱？"）且无障碍权限一旦被滥用后果严重。替代：按住说话 → 确认卡，两步内完成，无后台监听。
2. **云同步**：多设备/防丢数据的价值真实存在，但需要账号体系与云端成本，且原产品的备份明文问题说明这块做对很难。替代：CSV 一键导出，子女手动迁移。
3. **多账本**：家庭共享记账有真实需求，但需要邀请/成员/权限一整套交互，老人学不会。替代：不做——子女用自己的手机看父母的汇总页，比教会两代人共享账本现实得多。

## 四、方法收获

- 逆向的价值不在"抄功能"，而在**看清复杂度的分布**：原产品 214k 个方法里，真正服务"记一笔账"的不足 5%，其余是资产管理和商业化。
- schema version 2761 说明成熟产品的迁移包袱有多重——本项目 version 1，4 张表，每张表的意义现在都解释得清。
- 砍掉一个域 = 同时砍掉它的网络接口、权限、设置页和用户心智负担；裁剪决策应该发生在数据模型层，而不是 UI 层。
